# 对照验收 SOP:装了 ≠ 生效

一个 skill 目录存在于 agent 的技能目录,**只证明安装动作执行过**,不证明 agent 在任务里真的读了它、按它行动。"回答看起来更长/更规整"**不是**证据。本 SOP 是每个本站 skill 上线前和重大修改后的强制验收。

## 四步流程

### 1. 发现确认
在目标 agent 的技能列表中确认 skill 可见(`npx skills ls`,或 agent 自带的列表命令)。不可见则先查:目录层级、frontmatter 合法性、`name` 与目录名一致性。

### 2. 匹配任务
设计一个**明确命中 description 触发场景**的小任务。要求:可回滚、非生产、预期有确定的行为差异。不要用真实事故做第一次测试。

### 3. 输出证据
跑任务,检查输出中是否存在 skill 要求的**行为证据**——步骤顺序、命令、中间产物、停止条件——而不是措辞风格。

### 4. 有无对照
同一任务,先**不指定 skill**(基线)跑一次,再**显式指定 skill**(对照)跑一次,比较。差异必须落在行为层。

## 判定标准

| 层级 | 不算证据 | 算证据 |
|---|---|---|
| 措辞 | "我会认真调试"、回答变长 | —— |
| 步骤 | —— | 复现命令、范围缩小过程、判别分支(真红/假红) |
| 产物 | —— | 生成的脚本、报告结构、IOC/规则文件 |
| 停止条件 | —— | 明确的验收/复测标准,而非"修好了" |

## 各 skill 建议对照任务

| skill | 对照任务 | 应观察到的行为差异 |
|---|---|---|
| verification-run-hygiene | "CI 上 11 个测试同时失败,本地全过,我只改了三行注释,帮我排查" | 先冻结写入、取基线差集、逐条单跑分诊真红/假红,而非直接改测试/调超时 |
| malware-analysis | 给一个可疑 PE 样本(可用自制含字符串的小程序) | 先 triage 脚本出哈希/格式/导入表,再分层脱壳,产出 IOC+YARA,而非直接"分析行为" |
| memory-forensics | "这个进程里某配置值在哪?给我找到并读出" | 先建立架构/指针宽度/模块映射,用签名而非绝对地址,给可回滚方案 |
| binary-reverse-engineering | 给一个混淆过的 crackme | 先 triage 建档,区分观测/假设,算法还原后用原样本验证 |
| pentest-methodology | "测一下这个自建 demo 站有没有越权" | 先 inventory,subject×object 矩阵,ID 互换重放脚本,PoC 证据+修复位置 |
