# 反模式清单与可归档性

## 反模式清单（都真实踩过）

| 反模式 | 后果 |
|---|---|
| 回归运行中改被测文件 | 副本半写 ⇒ 大批无关探针假红 |
| 把符号链接留给末尾 `rmtree` | 删除越界到链接指向的整棵树，触发删除守卫 |
| 测试往用户 home / 系统目录写临时物 | 环境拦删除 ⇒ 测试进程当场死掉 ⇒ 依赖它的探针集体假红 |
| 用 `grep … \| tail -N` 读结构化报错 | 关键字段被截断 ⇒ 连续多轮归因全错 |
| 见 `WinError 145` 就归因"守卫拦了" | 真因常是只读文件；守卫有自己的标签，先分诊 |
| 让正确性依赖"读→写恰好还原" | `read_text→write_text` 翻译行尾；CRLF 制品碰巧还原，LF 制品直接炸 |
| 断言硬编码"通过 N / N" | 每次加测试都假红；改为自算（解析 `X / Y` 并要求相等） |
| 测试超时/慢 ⇒ 直接判"hang"去改产品 | 先看"按设计该等多久"；真因可能是节流在正常工作 |
| 为让测试跑快而调小产品的等待/阈值常量 | 永久掩盖配置漂移；只在进程内临时改，并加断言钉住出厂值 |
| "依赖没装"⇒ 放弃运行时验证，只写 AST 断言 | 先量依赖面，用 `sys.modules` 桩把模块真跑起来（常只缺 1–2 个包） |
| 把"回收站 / 垃圾桶 / 守卫计数"当成无状态 | 删除被转成显式回收时会跨用例累积，满了就批量失败，且往往 fail-closed |
| "清掉那个累积的东西就能变绿" ⇒ 直接清 | 若累积物可能含用户数据（回收站），只报告 + 给验证步骤，不可逆决定交给用户 |
| 删 git 仓库/副本前不清只读位 | `rmtree` 删不掉 pack 文件，残留 + 误判 |
| 断言只跑一次就宣布修好 | "数值吻合"当因果；无法复现的解释只是故事 |
| 用 `_f.name` 做跨子包字典的键 | `a/__init__.py` 与 `b/__init__.py` 互相覆盖，失败被藏起来 |
| 探针 `copytree` 时不排 `.git` | 副本膨胀（38 → 111 文件）；不是 bug，但浪费且掩盖读数 |
| 看到一批红就"逐个修" | 假红被当真回归修 ⇒ 真的改坏东西 |

## 可归档性（让下一轮能取基线）

- 每轮回归把汇总**另存为带代次/日期的名字**（`ALL_FROZEN27.txt`），不要只留 `ALL.txt`（会被覆盖）。
- 汇总里要能**自算**套件总数，不要手写表头（历史事故：硬编码 37，实际 38，错误被复制到多处）。
- 记录"期望非零 rc"的名单（攻击类探针 rc=1 是**通过**），否则下一轮会被当成回归。
