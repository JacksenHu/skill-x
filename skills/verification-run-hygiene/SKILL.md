# 验证运行卫生（Verification Run Hygiene）

## 这个技能解决什么

**"我改的代码没问题，但一大批测试同时红了。"** 这句话在真回归与假红之间，
而**两者处置方式完全相反**：真回归要改代码，假红要改验证环境。
把假红当真回归去"修"，会真的改坏东西。

本技能给出一套可判别的流程，以及一组从真实事故里换来的硬纪律。

---

## 纪律 1（最重要）：**验证期间禁止任何写入**

回归一旦启动，**连"顺手改一行注释"都不行**。

**为什么**：很多探针会 `shutil.copytree(被测树, 临时目录)`。你在运行中改文件，
副本就可能停在**半写状态**（截断的文件 / 语法不完整的模块）⇒ 副本里的工具崩掉 ⇒
**一大批与被改文件无关的探针集体判红**。

**症状特征**（认出来就不用慌）：
- 红的数量突然变大、横跨多个不相关模块；
- 失败日志里**没有**具体的断言明细，或直接是 traceback；
- **同一条探针单独跑就过**。

**处置**：停掉回归 → 冻结全部写入 → 重跑。不要分析、不要"修"。

---

## 纪律 2：**测试自己造的破坏面，必须自己收干净**

不要指望通用的清理函数替你判断边界。

**真实事故**：一个逃逸测试在临时根里建了一条**指向系统临时目录**的符号链接，
段末 `shutil.rmtree(临时根)` 扫到了它。删除守卫报的 `count:257` 就是
**整个系统临时目录的体量** —— 也就是说这次 `rmtree` 已经越界成
"要不要把整个 Temp 目录删掉"，**守卫是唯一挡住它的东西**。

**规则**：
- 测试里建的**符号链接**，用完**当场 `unlink()`**，不要留给末尾的统一清理。
- **不要假设 `rmtree` 不跟随符号链接** —— 行为依平台与 Python 版本细节而定。
- 清理只作用于**你自己创建的根**，且**形状校验**后才删（拒删含意外内容的目录）：
  ```python
  if not {e.name for e in d.iterdir()} <= KNOWN_NAMES:   # 形状不符 -> 拒删并登记
      refused.append(d.name); continue
  ```
- 临时物**集中在一个根**下，末尾**只删一次**（既快，也不容易踩到"批量删除"阈值）。

### ★ 但"末尾只删一次"有个致命前提：**它只在正常退出时生效**

**真实事故**：一个探针开头建临时树、末尾 `rmtree`。
一次 **runner 超时把它 kill 掉** ⇒ 末尾清理根本没执行 ⇒ 留下 **1368 文件 / 165 MB** 的树。
**下一次运行**进来先删这棵树 ⇒ 又超时被 kill ⇒ **再留一次** ⇒ **自我延续，整整白烧一轮 30 分钟的全量回归**。

**规则（异常路径也要能自收）**：
- **幂等清理放在开头**：进入脚本先 `force_rm(自己的根)`，删不掉就**当场报错**。
- **"删不干净"必须显式报错**，不许 `ignore_errors=True` 之后默默继续：
  ```python
  def force_rm(p):
      if not p.exists(): return
      for r, _, fs in os.walk(p):
          for x in fs:
              try: os.chmod(Path(r)/x, stat.S_IWRITE)   # 只读文件（如 git pack）要先解锁
              except OSError: pass
      shutil.rmtree(p, ignore_errors=True)
      if p.exists():
          raise RuntimeError(f"残留删不掉：{p} —— 先手工清理再跑（不许带着残留继续）")
  ```
- **临时根要能一眼认出属于谁**（带前缀），并在产出物里写明位置。

### ★★ 但"按前缀通配清理"会删掉别人的东西 —— 收尾清理只能走**白名单**

**真实事故**：收尾清理写的是 `glob("scratch*")` 式的通配，以为"同前缀 = 都是我的临时物"。
结果扫掉了**另一个探针用作参照物的目录**（恰好同前缀但**不是临时物，是数据**）⇒
那个探针下一轮直接 `FileNotFoundError`，而且**它报的不是假阳性 —— 参照物真的没了**。

**规则**：
- 收尾清理**只清白名单里明确登记过的根**；不要用通配去"顺便扫干净"。
- 对"看起来像自己人、其实是数据"的路径，写一条 `KEEP = {...}` 并注明**为什么它不许碰**。
- 判据：**"名字像我的"不等于"它是我的"**。删之前问一句：*这个路径是不是别人读的输入？*

> ★ 顺带一条：被删参照物若与"对照侧"逐字节相同，那个探针**在构造上就是空转的**。
> 参照物应放在不会被清理扫到的位置，并**钉住指纹**。

## 纪律 3：**"数值吻合"不等于"因果成立"**

**真实事故**：树里新加了 `.git`（占 73/111 个文件），而多数探针的 `ignore_patterns`
没排 `.git` ⇒ 副本文件数从 38 涨到 111 ⇒ 看起来完美解释"删除变多触发守卫"。
**实测补完 `.git` 后：守卫计数一项没少。** 真因是纪律 2 那条符号链接。

**规则**：提出原因后，**先把它改掉再量一遍**，而不是改完就宣布修好了。

---

## 纪律 4：**一个解释如果只解释得通一次，就还没被验证**

**真实事故**：某探针在全量回归里报 `FileNotFoundError`，单独跑却通过。
解释"被我 kill 掉的回归留下残缺快照" —— 逻辑自洽、与现象吻合。
**但它在下一轮又复现了**。真因：另一个探针会把该探针依赖的参照物目录
**从当前树重建**，而那次重建会被删除守卫打断，留下残缺副本。

**规则**：给出机制解释时，**先问"我能不能主动让它再失败一次？"**
- 能复现 ⇒ 这是机理，可以据此修；
- 只在特定一次成立、无法重放 ⇒ 这是**故事**，继续查，不要据此改代码。

**推论**：如果某探针依赖一个**会被别人改写的参照物**，它的检查可能已经**静默空转**。
**检查必须能说出自己是否空转**（同源 ⇒ 醒目打印"本次对比无内容"）。
**"会无声变绿的检查比没有检查更坏"**。

---

## 纪律 5：**验证"拒绝类"断言必须读反向**

只读"持锁被拒 / 非法输入被拒"**无法排除**"无论输入如何都拒绝"这种假通过。
必须补一次**反向读数**：合法情形下它**应当正常工作**。

---

## 纪律 6：**"全为假"的批量读数，先怀疑量具**

**真实事故**：做同族产品对照，第一轮结果**全部**是"目录不存在"。
真因是**当前 shell 里 `APPDATA` 是空字符串** ⇒ 路径落成相对路径，**必然**不存在。

**规则**：
- **任何"全部为假/全部相等/全部为零"的批量结果，先做一次"量具自检"**：
  拿一个**已知必然为真**的样本过一遍同段逻辑。若它也是假 ⇒ 量具坏了。
- 环境变量、相对路径、编码、时区 —— 最容易让量具静默失效（它们**不会报错**）。
- 对照实验里，**"对照组"的作用就是量具自检**：对照组不合格 ⇒ 该轮全部读数作废。

**推论**：**同一套方法可以得出相反结论 —— 因为证据不同。** 每条结论都必须**当次实测**支撑。

---

## 纪律 7：**修"该清的没清"时，必须同时读"该保的有没有被误伤"**

清理/重置类修改，只验证"目标被清掉了"是不完整的——还必须验证：
- **该保留的确实还在**；
- **异常输入下不动手**（解析失败 ⇒ 原样跳过，不写回）；
- **无目标时不做无意义的重写**。

> **一个只会清不会保的清理工具，和不会清的清理工具一样不可用。**

---

## 纪律 8：**判"是谁在拒绝我"，要看对方自己的标签**

**真实事故**：清理临时目录时剩两个目录删不掉，报文 `[WinError 145] 目录不是空的`。
归因为"批量删除守卫被顶爆" —— **错**。守卫**有自己的签名标签**，
而那行报错里**一个守卫字段都没有** ⇒ 它根本不是守卫拦的。
判别性实验（只读文件 + `rmtree`）：真因是 **Windows 下 `rmtree` 删不掉只读文件**
（git pack 文件默认只读）；首次失败抛 `WinError 5`，外层再 `rmdir` 时表面报文变成 `WinError 145`。

**规则**：
- **先按签名分诊，再解释**：守卫 → 匹配它自己的标签；`PermissionError`/`WinError 5|145` → 权限/只读；
  `FileNotFoundError` → 竞争/残影。**没有该系统的标签，就不要用它来归因。**
- 删树前**先清只读位**，尤其目标是 git 仓库或从 git 取出的副本。
- 同一个 `OSError` 族里，**不同错误码可能只是"谁先抛"的差别**。

---

## 纪律 9：**报告里最关键的字段不要截断**

**真实事故**：连续三轮归因全错，因为一直用 `grep '<关键词>' 输出 | tail -N` 读守卫消息 ——
而 `tail` 恰好把 **`targets` 字段截掉了**（决定性信息：目标只有 1 个且是单文件）。

**规则**：
- 从结构化消息取证时，**先把关键字段完整打出来**，再看形状；截断的行**不足以支撑任何因果结论**。
- 长输出宁可**整段落盘到文件**再逐段读，也不要随手 `| head` / `| tail`。
- 报告给协作方同理：**别把最关键的字段写在会被折叠/截断的位置**。

---

## 纪律 10：**测试不该在用户 home（或任何共享目录）里增删任何东西**

**真实事故**：两个断言用了**真实**的 `~/.xxx.lock` 路径 ⇒ 在用户 home 下创建再删除 ⇒
环境保护机制**拦下 home 下的删除** ⇒ **测试进程当场死掉** ⇒
每个依赖它的探针都拿到红 ⇒ **十一个探针集体判红，而产品代码一行没错**。

**规则**：
- 需要真实路径语义的测试，**给代码留环境变量覆盖口**，测试把路径指到**临时区**；**生产默认值不变**。
- 覆盖要**覆盖到整段测试结束**；中途还原会让后面的断言又落回真实路径。
- 判据：跑完测试后 home 下那个文件**不存在**，且守卫触发数 = 0。

---

## 纪律 11：**要还原就写原始字节 —— 别依赖"读→写恰好还原"**

**真实事故**：`read_text` 把 CRLF 归一成 LF，`write_text` 又把 LF 翻译成 `os.linesep`，
**全 CRLF 制品"恰好"还原**；制品变成纯 LF 后，同段代码把它翻成 CRLF，字节断言失败。

**规则**：
- **还原 ⇒ 写字节**（`write_bytes(原件.read_bytes())`）；
- 别在注释里写"本制品是 CRLF 所以没问题" —— 把前提变成**不依赖前提**的写法，或加断言钉住；
- 同类易踩：**编码**（BOM / GBK）、**时区**、**区域设置**。

---

## 纪律 12：**测试跑得慢，先确认"慢"是不是产品在正常干活**

**真实事故**：端到端用例跑满 120 秒被 timeout 杀。第一反应"某处 hang"。
**真因是产品设计在正常工作**：两次操作之间**故意**有 30–60 秒节流。

**规则**：
- 超时/慢 ⇒ **先看"这段时间产品按设计应该做什么"**，再怀疑死锁。
- **别用"改小产品的等待参数"让测试变快**；只在该进程内临时改常量，
  **并加静态断言钉住出厂值**。
- 反向也一样：**测试要能证明"该等的时候它真的等了"**。

---

## 纪律 13：缺第三方依赖时，用 `sys.modules` 桩把模块**真跑**起来

**"依赖没装"不是"无法运行时验证"的理由** —— 结构对 ≠ 行为对。

**做法（四步）**：
1. **先量依赖面，不要凭印象**：把顶层 import 全打出来，数出**真正缺**的几个（常常只缺 1–2 个）。
2. **只桩"行为"，不桩"逻辑"**：只把触碰外部世界的点换成鸭子类型替身；**被测逻辑保持真代码**。
3. **按依赖顺序重定向副作用路径**：注意 `from .config import PATH` 会**绑定副本** ⇒ 必须**先改常量、再 import**。
4. **如实登记桩的固有边界**：桩掉了什么，就**没能验证**什么。

---

## 纪律 14：**"删除"可能被转成"移入回收站"——它会累积，然后开始失败**

**真实事故**：环境的安全删除钩子把删除转成 `trash`。**回收站被灌满**
（实测约 20 万项 / 数 GB）⇒ `trash` 开始**批量失败** ⇒ 因为 **fail-closed** ⇒
之后**所有**删除都被拒 ⇒ 依赖"删树 + 重建"的探针**集体不稳定**，而产品代码一行没错。

**规则**：
- 遇到删除类拒绝，**先量三件事**：① 拒绝报文的**原因字段**（完整、不截断）；
  ② 共享状态（回收站）的**条目数与体量**；③ 磁盘余量（排除"没空间"）。
- **别把"累积型资源"当成无状态**：守卫计数、回收站、临时区配额、文件句柄 —— 都在**跨用例累积**。
- **不是自己该清的东西，不要自己清**：回收站里可能有用户想恢复的文件。
  正确做法是**报告 + 给出可复现的验证步骤**，把不可逆决定交给用户。

---

## 纪律 15：改动一个**被别人断言**的代码块时，优先"走原来那条语句"

**首选解法是让新路径与旧路径并存，而不是替换那句被断言的语句**：

```python
if cancel is None:
    await asyncio.sleep(delay)              # 旧调用点路径逐字未变
elif await cancellable_sleep(cancel, delay):
    ...
```

- 收益：**既有断言一个字都不用改**，且"旧行为不变"升级为**结构保证**。
- 改被断言的代码前，**先搜"谁在断言它"**（字符串、行数、AST 形态），把连带成本量出来。
- 如果必须替换，**改判据要单独说明"为什么这是度量跟着事实走"**。

---

## 纪律 16：工具遇到自己的格式漂移时，用「**宽容读 / 严格写**」

- **读取端宽容**：认全部历史格式；用了兜底要**打印出来**（不静默）。
- **写入端严格**：统一成**唯一**规范格式，并打印规范化动作。

⇒ **漂移只会发生一次**。工具收"有格式要求的输入"时，**要么校验并规范化，要么明确报错**。

---

## 纪律 17：测试**改了全局状态**，就必须配一条"已还原"的断言

进程级全局状态（信号处理器、`os.environ`、cwd、locale、`sys.path`、随机种子、logger）
一旦被测试改动，**会污染同一进程里后面跑的所有检查**。

**规则**：
- 改之前**记下原值**，改之后立刻 `try/finally` 还原；**并且断言还原成功**。
- 更稳：**封成上下文管理器**，让"忘记还原"在结构上不可能发生。
- 断言**"本组结束时不留下副作用"**。

---

## 纪律 18：验"信号/事件驱动"的代码，走**真实投递路径**，不要直接调回调

直接调用回调只能证明"**这个函数被直接调用时**行为对"，证明不了"事件真的能送到它"。

**规则**：
- 断言覆盖三条：① 注册成功；② **真实投递**下的行为（如 `signal.raise_signal`）；③ 退出后**已还原**。
- **平台不支持的路径要登记，不要假装覆盖**。
- 只"直接调回调"时，必须在报告里**写明是间接验证**。

## 判别流程：真回归 vs 假红

```
1. 冻结全部写入（纪律 1）。任何诊断都不要先改代码。
2. 取基线：找到"上一次全绿"的回归归档，把 rc!=0 的集合与本次做差集。
     · 只有本次新增的失败才值得查；基线里本来就红的属"期望红/已知项"。
3. 逐条单独跑失败项（脱离 runner）：
     · 单独跑就过  -> 与运行环境/顺序/并发有关（往第 4 步查）
     · 单独跑也红  -> 真回归，去看它的具体断言明细
4. 检查共享的外部资源：
     · 先按签名分诊"是谁在拒绝我"（纪律 8）
     · 把拒绝报文的关键字段完整打出来（纪律 9）
     · 全局计数器/守卫/配额是否被前序用例推高？
     · 临时目录里有没有前几轮被中断留下的残留？
     · 探针依赖的"参照物"会不会被另一个探针改写？（顺序依赖 + 静默空转）
     · 有没有残缺副本把下一轮的同一条探针带崩？
     · 测试自己有没有在用户 home / 共享目录里增删东西？（纪律 10）
5. 找到假设 -> 改一处 -> 重跑 -> 读新的读数再决定，不要凭"看起来对"收工。
6. 复现才算机理（纪律 4）：能主动让它再失败一次，才据此修。
```
